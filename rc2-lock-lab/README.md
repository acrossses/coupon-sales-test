# 保存とコピーの単独検証ラボ（公開前）

目的は、iPhone Safari通常タブでのWeb Locks・保存順序・クリップボードを調べること。正式版への組込み、台帳API、購入履歴API、Worker・D1は実装しない。ダミー在庫・ダミー文面のみで、本番キーも使わない。ページを公開するには、このDraft PRとは別にマージ・Pages公開の承認が必要。

## 分離と保存形式

操作する保存キーは次の4つだけ。キーを列挙した全削除は使わず、初期化もこれらを名前で指定する。

- lockLab_v1_data：ダミー在庫・取引・版番号・同期状態
- lockLab_v1_guard：データセットIDと取引ID→purchaseIdの対応表
- lockLab_v1_buyers：ダミー台帳
- lockLab_v1_backup：補助情報

同一オリジン内のラボ専用ロック名はlockLab_v1_write。業務更新、ダミー台帳、補助情報を同じロックへ載せる。確認画面・模擬の応答待ちはロックの外。通信APIはなく、CSPでも接続を拒否する。BroadcastChannelはラボの2タブ試験の合図だけに使う。

識別情報を失った場合、読み取り・再読込・通常保存では新IDを作らない。対応表は主データと別キーに単調追加し、旧版が主データだけを書き戻した後も検出できる。対応表の保存後に主データ保存が失敗しても、未使用の対応が残るだけで取引完了とは扱わない。これは複数キーの原子的保存ではない。サイトデータ全体の消去、対応表も含む破壊、購入履歴サーバーとの照合はこのラボの保証範囲外。

主データ保存成功・補助情報失敗は別警告。補助情報失敗で主データを巻き戻さない。ID欠落は復旧待ち、historyの型不正は未同期へ倒す。固定文面・copyIntentAtを保持した未送信の再コピーを可能にする。

## 自動テスト

リポジトリのルートから：

```sh
node --test rc2-lock-lab/tests/lock-lab.test.cjs
```

NodeのFIFO模擬ロックとメモリ保存先を使用する。実ブラウザ・Safariの証明にはならない。画面の「20回の競合」は実Web Locksで2つの呼出元を動かす反復試験であり、実2タブ試験とは区別する。

## ローカルの画面確認

リポジトリをlocalhostで静的配信し、/rc2-lock-lab/を開く。Web Locksは安全なコンテキストが必要。iPhoneからのHTTP LANアクセスを実機試験の代用にせず、公開承認後のHTTPSを使う。noindexは検索向け指定でありアクセス制御ではない。

## 実機手順・判断

1. 「ダミーを準備」。同じラボを別タブにも開く。実機のiOS/Safari版、日時、操作条件を記録する。キーは不要。
2. 「2タブ同時確保を予約」を片方で押す。1.5秒後の結果がapplied 1つ・changed 1つ、取引1件・rev=1か確認。反復は「20回の競合」で自動化する（各回初期化）。
3. 確認画面を開いたまま別タブで登録する。別タブの保存が完了し、確認側は承認後に変更ありとなること。
4. 文面準備→送信済み確認→模擬同期受付の500ms待ちと、別タブの新規登録を重ね、両方残ること。
5. 保存失敗・補助情報失敗・ロック非対応をそれぞれ試す。主データ失敗は成功と表示しない。補助情報だけ失敗した場合は主データ保存済みと別警告。非対応は閲覧専用。
6. 「旧版による識別情報の喪失」を試した後、ページを再読込。復旧待ちのままで新しい取引IDが作られないこと。ラボの初期化だけで元へ戻す。
7. 未送信取引で、待ち0・500・2000・5000msの1ボタン方式を試し、貼付欄へ手動で貼って固定文面と一致するか確認。準備後の再コピーでも文面と時刻が変わらないこと。
8. ①文面準備→②コピーの2ボタン方式も確認する。②は最新の保存状態を同期的に確認し、ロック待ちを挟まず新しいタップでコピーする比較用。ページを離れたり、別タブで送付済みになった場合の動作も確認する。

0msの成功だけで1ボタン方式を採用しない。待ち条件で失敗があれば、2ボタン方式を候補とする。Web Locksの保存整合性とコピー方式の判定は分ける。2ボタン方式はコピー直前に状態を読むが、非同期クリップボード処理全体をロックで囲うものではない。正式版への採用時には、対象固定・同時操作・ユーザー操作制約を含めて別途レビューする。実機で確認していない結果を合格と書かない。

## ローカル検証結果（2026-11-20 JST）

Node v26.13.0で24/24合格。ローカルのChatGPTブラウザでは実Web Locksの20回競合が20/20合格。実2タブの同時確保はapplied 1つ・changed 1つ、rev=1・取引1件を確認した。確認画面を開いている間も別タブの保存が進み、確認後に変更ありとなった。模擬受付の待ち中の追加登録と受付記録が両方残った。主データ保存失敗では内容不変、補助情報だけ失敗した場合は業務データ保存済みと別警告、非対応模擬では操作が無効になった。識別情報を失う模擬操作後は再読込しても復旧待ちとなり、新IDを生成しなかった。ブラウザの実行時エラーは0件。クリップボードへの実書き込み、iPhone実機、アプリ切替・タブ破棄は未確認。
