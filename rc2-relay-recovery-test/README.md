# RC2 保存済み新着の再通知テスト版

RC2に保存した後で完了通知が失敗し、ページを再読み込みすると通知を回復できなくなる問題を確認する独立テストページです。
PR #2のHEAD f40dce233e03984232f715f4c23eeefd69843c66 のテスト用HTMLを基にしています。正式版RC2・PC・Workerは変更しません。

## 操作

テストWorkerとダミーデータのみを使用してください。新着を登録して通知に失敗した後、ページを再読み込みし、同じWorkerから新着を取得します。
保存済みURL・商品名・既知店舗が完全一致すると「保存済み：完了通知を再送」が表示されます。取得だけでは通知しません。
ボタンを押すと完了通知だけを送ります。在庫の追加・再登録は行いません。失敗時は同じボタンで再試行できます。
商品・店舗の不一致、具体的店舗名を受信情報から確定できないotherは復旧通知しません。入力を変更して古い通知ボタンを押しても送信しません。

## 保存領域

coupon_sales_relay_recovery_test_v1 系の専用キーを使用します。正式版およびPR #2のテスト在庫を読み込まず、移行もしません。
したがって既存のテスト在庫の直接救済ではなく、このページ内で登録・再読込したダミー在庫で復旧経路を確認します。
受信キーは従来どおり保存せず、再読込後にテスト用キーを再入力します。実キーをGitHubやチャットへ記載しないでください。

## 検証

Nodeで `node --test rc2-relay-recovery-test/*.test.cjs` を実行します。
28件合格: 既存スクロール・登録確認19件、新着復旧9件。
復旧のテストでは在庫不変、取得だけで未通知、再通知失敗後の再試行、商品・店舗・URLクエリの不一致、曖昧なother、在庫消失、古いコールバック、キー消去を確認します。
受信側実コードを抽出し、DOM・HTTP応答を模擬したオフライン検証です。

別途ローカルでは既存Workerコードと実SQLiteでも再通知→confirmed→新着除外→同URL再送で非復活を確認しています。
Cloudflare実D1、デプロイ済みWorker、iPhoneでのこの復旧経路の確認は未実施です。
Workerが存在しないconfirm IDにも成功を返す既存挙動は修正していません。今回の変更は受信側の再通知復旧に限定します。

mainへの直接書き込み、マージ、自動マージ、デプロイは行っていません。
