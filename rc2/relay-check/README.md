# 本番ダミー送信確認

本番Workerに確認用ダミーを1件だけ追加するための独立した画面。正式版RC2と同じGitHub Pagesオリジンで配信する。実クーポンの入力欄や受信・完了通知・削除機能はない。

送信先は https://kensho-relay.coupon-relay-hub.workers.dev/api/send に固定。ページを開いただけでは通信しない。利用者が保存済みのSENDER_KEYを画面へ直接入力し、送信ボタンを押す。キーをチャット、リポジトリ、環境変数、ログへ渡さない。キーはストレージへ保存せず、試行終了・ページ離脱時に入力欄を消去する。

ブラウザに保存するのはダミー識別UUIDだけ。保存キーcoupon_sales_prod_dummy_check_v1は在庫・取引・台帳と別。URLは予約済み無効ドメインexample.invalidのダミーで、このURLへアクセスはしない。同じブラウザの再送・再読込は同じURLを使い、既存Workerのdigest UNIQUEによって重複挿入を防ぐ。別ブラウザや保存領域消去後は別ダミーとなるため、同じブラウザで確認する。

## 検証

`node --test rc2/relay-check/sender.test.cjs`

テストは模擬通信とダミーキーのみ。本番DBへの書き込みはしない。実際の送信は利用者の明示操作で行い、商品名を記録する。正式版RC2でその商品名だけを登録し、ローカル保存後の完了通知と同じダミーの再登録なしを確認する。

既存のtest-001は出所未確認のため保留。新ダミーの確認成功後も新着が1件残る場合があり、それを削除・完了通知しない。新着総数ゼロを成功条件にしない。在庫の比較は新ダミーの対象商品について行う。

公開前: この追加ファイルだけを作業ブランチ・Draft PRに登録し、マージによるPages公開は利用者の承認を得る。Worker、DBスキーマ、Secrets、既存RC2本体は変更しない。
