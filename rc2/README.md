# 正式版 RC2：クラウド新着・再通知（リリース前）

既存のRC2へ、PR #3で検証したクラウド受信・保存後の完了通知・再読み込み後の手動再通知を追加する候補です。登録の最終確認はページ内ダイアログで行います。取得だけでは登録・完了通知しません。保存済み新着はURL・商品・既知店舗が一致するときだけ再通知でき、在庫を追加しません。その他の交換先や不一致は手動確認を求めます。

## 保存データ

同じオリジンの既存RC2データを利用します。以下のキーとJSON形式を維持し、テスト版からの自動移行は行いません。

- 在庫・取引：`coupon_sales_release_rc2` / `coupon-sales-release-rc2-v1`
- 購入者台帳：`coupon_sales_release_rc2_registry_v1` / `coupon-buyer-ledger-rc2-v1`
- バックアップ日時：`coupon_sales_release_rc2_backup_evidence_v1`

受信キーは保存しません。入力欄に直接入力し、再読み込み後は再入力します。接続先は既存の本番Workerオリジンだけに固定し、任意のURLやテストWorkerへキーを送信できないようにします。ページを開いただけでは通信しません。PC・Worker・テスト版のコードは変更しません。

## テスト

`node --test rc2/tests/*.test.cjs`

すべてダミーデータと模擬通信で検証します。在庫の利用可能・確保中・送付済み、確定済み文面、購入者台帳、破損データの書き込み停止、通知失敗後の復旧、登録確認中の状態変更、スクロール取消を確認します。

## 公開前の条件

2026-11-19 JSTに、本番Workerの `/api/pending` へ認証情報なしでGitHub PagesオリジンからのOPTIONS事前確認を実施しました。HTTP 404、Access-Control-Allow-Originなしでした。この状態ではブラウザからの認証付き取得はできません。本番キーの送信、実データの取得・更新、Workerの変更・デプロイは行っていません。

別PRで本番WorkerのコードとCORS・認可・confirmの応答を確認・修正し、正式版の接続元だけを許可してから、本番公開を判断してください。未知のconfirm IDにも成功を返す既存Workerの挙動、送信後に応答が失われるケースは未解決です。PR #3由来のテストプレビューでの実通信成功を、この正式版候補そのものの本番通信確認とは扱いません。

取り込み・公開前に、利用中の在庫・取引と購入者台帳それぞれのバックアップを保存してください。公開オリジンが変わるとlocalStorageは共有されないため、移行は別途確認が必要です。
